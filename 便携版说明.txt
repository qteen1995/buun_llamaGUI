buun-llama-cpp 控制台 —— 便携版
================================

怎么用
------
1. 双击 buun_llama_gui.exe 就能开界面（已经内含 Python 和 tkinter，不用装任何东西）。
2. 第一次打开后：
   · 顶栏「引擎目录」选你的 buun-llama-cpp 仓库目录或 build\bin
     （要能找到 llama-server.exe），点一下「探测参数支持」；
   · 「模型库」页填扫描目录 → 扫描 → 选一个模型 → 设为当前；
   · 回「服务」页点「加载 LLM 模型」。

三种运行模式
------------
服务     OpenAI 兼容的 HTTP 服务，对外只有一个端口（默认 1233）。
         服务页有两种互斥的「运行方式」：
           单模型网关 = 本程序负责按请求换模型（默认）
           多模型路由 = llama-server 自己驻留多个模型；此时网关只做透传，
                        模型来源请用「导出路由预置 INI」生成预置文件
                        后填到「路由预置文件」里
对话     终端里多轮对话（llama-cli）
生成     一次性生成（llama-completion），给提示词出结果就退出

三个必须注意的点
----------------
· buun 的 KV 缓存默认档位是 vbr（动态量化），它会按模型几何自动选 turbo 阶梯。
  turbo / TCQ / VBR 的 KV block 是 128 个值，要求模型 head_dim 能被 128 整除
  （Qwen3 系、Gemma4 都行；bert 系如 bge-small 的 head_dim=64 会直接被引擎拒绝）。
  启动器会提前读 GGUF 拦住并告诉你怎么改（把 K/V 档位显式设成 q8_0 之类）。
· turbo*_tcq 档位依赖仓库 codebooks\ 里的码本文件；启动器会自动找到并通过
  TURBO_TCQ_CB / TURBO_TCQ_CB2 注入，仓库里缺文件时会写警告。
· 引擎缺 CUDA 运行时 DLL 时 Windows 只会让进程秒退（0xC0000135）。
  启动前会静态解析依赖表，缺什么、该补哪个目录都会写进运行日志。

设置存在哪
----------
就是本目录下的 config\ 文件夹 —— **便携**：不写注册表、不碰 %APPDATA%。
把整个文件夹（或者这两个 exe + config 文件夹）拷到 U 盘、另一台电脑，设置跟着走。
想重置设置，直接删掉 config 文件夹即可。

  config\app.json                     软件级设置（引擎路径、模型目录、界面偏好…）
  config\models\<模型名>.json         每个「配过参数的模型」一个文件，几 KB
  config\cache\scan.json              模型库扫描缓存（可删，下次重扫）
  config\router-preset.ini            多模型路由的预置文件（用时生成）
  config\selftest.log                 自检输出

· 模型配置文件名 = 模型库里的显示名（非法字符换成 -，重名自动加 -2），
  文件内部的路径才是权威标识，所以给模型改名不会丢设置。
· 老的单文件 config.json 会在首次启动时自动拆开，原件改名成
  config.legacy.json 留退路（内容一字不改，想回滚就把它改回 config.json）。

三个新加的实用功能
------------------
1. 上下文长度留空 = 自动
   「加载参数」页的「上下文长度」默认留空，此时引擎会从模型的训练上下文起算、
   按可用显存往下缩，KV 成本按「最低档位下限」的单价计价。实测同一台机器上跑 27B：
     下限 turbo1_tcq → 262144、turbo8 → 156672、f16 → 80640
   也就是说下限压得越狠，能开的上下文越长、KV 精度越低。
   相关：同一页的「显存保留余量」（--fit-target）越大，自动算出的上下文越短。

2. 底部运行状态条
   实时显示生成/提示处理速度、当前 KV 档位、上下文长度与已用比例、VBR 是否降级。
   数据全部来自引擎自己的 /props、/slots 和响应里的 timings，不需要额外开关。
   例：运行状态：生成 365 t/s · KV vbr·当前 f16 · 未降级（下限 4.12 bpv） · 上下文 60 / 16384

3. 多模态投影按需进显存
   「加载参数」页的「投影按需进显存」（--mmproj-gpu-swap）：投影文件先留在内存，
   只有真的来了带图片的请求才换进显存，用完换回去。需要先指定多模态投影文件，
   且只有 llama-server 支持。

两个 exe 的区别
--------------
buun_llama_gui.exe        正常使用（没有控制台窗口）
buun_llama_gui_debug.exe  带控制台，用来排查问题：
                        buun_llama_gui_debug.exe --selftest   跑一遍自检
                        自检结果也会写到 config\selftest.log

说明
----
· 程序只负责「管理并启动 llama-server」，模型推理本身由你自己的 llama-server 完成，
  所以引擎目录必须指向你编译好的 buun-llama-cpp。
· 首次启动较慢（单文件 exe 要先解压到临时目录），之后是正常速度。
· 如果 exe 放在没有写权限的目录（例如 Program Files），配置会自动改存到
  %LOCALAPPDATA%\buun_llama_gui，界面启动日志里会写明。
